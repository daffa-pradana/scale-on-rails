# System Design, from a Rails Background

My path from Rails developer to system design, done in public.

Instead of nine throwaway exercises, it grows **one ticketing app** phase by
phase: request tracing, booking under concurrency, caching, background jobs and
payment webhooks, load balancing, read replicas, rate limiting and circuit
breakers, and observability. Each phase is tagged, so any checkpoint can be
checked out and redone from scratch.

If you're also a Rails developer who wants to learn system design, feel free to
follow along — fork it and start from the `phase-0` tag.

## Where to start

- [learning-path.md](learning-path.md) — the syllabus: reading, gates, progress
- [PROJECT.md](PROJECT.md) — the app, what each phase builds, and how checkpoints work
- [docs/phases/](docs/phases/) — my notes per phase, written as I go
